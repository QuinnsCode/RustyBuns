The Game Engine

Physics and netcode: how a shared game stays fair, and how it stays smooth.

Fair is easy. Smooth is easy. Both at once, over the internet, is the whole job.

Two halves: the referee (fair), then the in-betweens (smooth). The buffer engine is the one deep part, at the end.
The picture first

A football match on the radio

You hear the match a little late. The referee on the pitch already made the call.

  • The referee sees the real match. Their call is final.
  • You hear it half a second later. You still enjoy it.
  • A good commentator fills the gap, so it never sounds like it stops.

In our games, the server is the referee and your screen is the commentator. The commentator is not allowed to invent goals.

Physics

Rules that step, not rules that flow

  • The game moves in ticks: many small steps every second.
  • Each tick, everything moves a little, falls a little and bumps a little.
  • The same start and the same inputs give the same game, every time.
  • So a test can play a whole game with no screen at all, and check it.

A flip book never surprises you. That is a compliment.

Fair

The server holds the true game

Your screen sends

Only what you pressed. Not where you are.

The server decides

It runs the rules and makes the true frame.

Everyone gets

The true frame. Some games send each player only what they can see.

You cannot tell the referee you scored. You can only kick the ball and hope.

One game room is one Durable Object (talk 0). Say "the referee's notebook" again.
The problem

True frames arrive late, and not on time

The internet is a post office. Most letters come fast. Some come late. A few come together.

  • Draw each true frame the moment it lands, and the game stutters.
  • Wait for every frame, and the game feels slow.

Lag is the referee's whistle arriving late. Stutter is three whistles arriving at once.

Smooth

Draw the moments in between

Your screen keeps the last few true frames, and draws smooth moments between them.

  • It stays a tiny bit behind the newest frame, on purpose.
  • So there is always a next frame to slide toward.
  • When a frame is late, the slide simply takes a little longer.

The commentator stays one breath behind the match, so they never run out of words.

The cute specific

The buffer engine: smoothing twice

A new engine in Rust, running as WebAssembly. It smooths in two places, not one.

Two commentators: one at the stadium gate, one in your living room. The referee still has the last word.

This is the one deep part of the talk. Say what it does: a buffer at the edge, close to the player, runs a little ahead of the server's true frames; the screen smooths between what the edge sends. Do not explain how far ahead, how it guesses or how it corrects.
Why two places

The long trip and the short trip

  • The trip from the server to the edge can be long. The edge covers that wait.
  • The trip from the edge to you is short. Your screen covers that one.
  • When a guess is wrong, the next true frame fixes it gently, not with a jump.

Like a relay race. Each runner only has to be good at their own stretch.

What the games prove

The engine in real games

Headless games

Robots play thousands of games with no screen, to test and to balance.

A cheater cannot read what the server never sent. That is the cheapest anti-cheat there is.
