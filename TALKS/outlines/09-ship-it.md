> Lots of change all day, the main code never stops, and one person signs the last step.

- Robots check it makes sense :: The code is read for mistakes before anything runs. :: a robot with a red pen
- The tests of every app it touches :: Only the apps this change could break. :: a few apps lit up on a big map of apps
- One walk-through test :: A new feature brings one test that uses it the way a person would. :: footprints walking through an app screen
- What people do, not what a cat could do :: We test the everyday path, plus the failure people actually hit. :: a cat on a keyboard, crossed out
- Green or red :: Green, and Mervin merges it. Red, and it waits for a fix. :: a traffic light

## Release rings
- The main code never freezes :: Changes keep landing all day. :: a busy conveyor belt that never stops
- Rings behind it :: Safety lives in rings behind the main code. They only move forward. :: rings stepping outward behind a belt
- Hour, day, week :: Each ring is a taste test with a bigger table. :: three rings labelled hour, day, week
- A ring waits for the one below :: It moves only when the ring inside it has stayed green. :: one ring waiting for a green light on the inner ring
- The express lane :: One change the owner sends straight through every ring, with no waiting. :: an ambulance lane on a busy road
- The soup earns its way :: From the kitchen to the dining room, one ring at a time. :: a bowl moving out through the rings

- A red ring stops, the rest keep going :: Everyone else keeps working. :: one red ring, the belt still moving
- Ester names the change :: Ester finds which change broke it. :: a detective pointing at one change

- Secrets behind a fingerprint :: They unlock only when the owner touches the sensor. :: a finger on a sensor
