# What Rusty Buns Is
> One app, three places, no rewrite. Every slide comes back to the plug picture.

## One plug that fits every socket
- What Rusty Buns Is :: Write an app once. Run it on a laptop, a server or the cloud. :: a desk lamp with a plug that changes shape
- One lamp, many countries :: You travel with one lamp. Every country has a different socket. :: a row of world wall sockets, all different
- A new lamp in each country? :: Most people write the app again for each place. :: a pile of lamps by a suitcase
- A bag of adapters :: Some people carry adapters, and lose one every trip. :: a tangle of travel adapters
- A plug that changes shape :: Rusty Buns fits the wall. The lamp stays the same. :: one plug morphing to fit three sockets
- The lamp is your app :: The lamp is your app. The wall is where it runs. The plug is our problem, not yours. :: lamp, plug, wall, each with a label
- One idea for the whole talk :: One app, three places, no rewrite. :: one box with three arrows out to a laptop, a server and a cloud

## The three sockets
- Three places an app can live :: A laptop, a server and the cloud. Each one is a different wall. :: three walls with three sockets
- On a laptop :: One file you double-click. The app opens in your browser. Your data stays at home. :: a kitchen at home, a laptop on the counter
- On a server :: The same file on one rented computer. Cheap, and it holds many small apps. :: a food hall with many stalls
- In the cloud :: On Cloudflare, close to every visitor. Nobody looks after a server. :: a chain of shops, one on every corner
- Each socket speaks a different language :: A laptop keeps data in a file. The cloud keeps it in a database far away. :: a file folder beside a far-off warehouse
- Three copies is a hobby :: Write it three times, fix each bug three times, watch the copies drift apart. :: three lines that start together and slowly split
- Moved, not rewritten :: With Rusty Buns, the same app moves between the three. :: one box sliding along a track past three stations

## Five parts, and a twin for each
- Every app needs the same five parts :: Almost every app with a server is built from the same five parts. :: five simple icons in a row
- The front door :: Requests come in. Answers go out. :: a shop door with a bell
- Live messages :: Fast talk, both ways, like a game or a chat. :: two walkie-talkies
- Storage and memory :: Storage is data you keep. Memory is fast data a restart throws away. :: a filing cabinet beside a whiteboard
- Who you are :: Sign-in. :: a name badge on a lanyard
- The cloud gave each part a shape :: You write your app against those five shapes. :: five shaped holes in a board
- Each shape has a laptop twin :: Same shape, different socket. The app cannot tell which one it got. :: five shapes, each with a matching twin below it

## One list, three places
- You write one short list :: The list says what your app needs. Nothing more. :: a short shopping list on a fridge
- The tool does the rest :: It reads the list and sets up each place. :: the list, three arrows, three places ready
- No Rusty Buns code in your app :: Your app does not know we exist. :: an app box with no logo inside
- Leaving takes one delete :: Delete the list and walk away. We would be sad, quietly. :: an open door and a small sad bun
- The price comes first :: Before anything goes to the cloud, it lists every paid piece. :: a receipt shown before the purchase
- It cleans up after itself :: One command removes everything it made. :: a broom and an empty, tidy room
- Break it for free :: No cloud account needed. A helper can start, test and break the real app on a laptop. :: a crash-test dummy on a laptop

## TypeScript everywhere, Rust for the heavy lifting
- Almost all of it is TypeScript :: The page, the server and the settings: one language. :: one thread running through three beads
- Some jobs are too slow :: Sound, physics, 3D shapes and big puzzles need more speed. :: a heavy weight on a small shelf
- Write only that part in Rust :: The heavy part, and nothing else. :: one gear in a machine swapped for a steel one
- Rust runs in three places too :: On a laptop, on a server, or inside the page as WebAssembly. :: a race engine in a family car
- Every Rust part has a twin :: A TypeScript copy that gives the same answer. :: an actor and an understudy with the same script
- No Rust? The twin plays :: If Rust cannot load, the twin takes over. The family car still gets you to the shops. :: the understudy stepping on stage
- Why "Rusty Buns" :: Rust for the fast parts, Bun for the rest. It started with grass: a game needed faster grass. :: a lawn growing into a building

## What it is, and what it is not
- It sits on top :: It is not a new way to write web pages. Keep the tools you like. :: a cake with one thin top layer
- A framework for frameworks :: It works on top of the popular web frameworks. A meta metaframework. :: nested dolls
- Not a phone app maker :: A phone app should feel like the phone. It can still talk to the same cloud. :: a phone and a cloud joined by a line
- Safe for AI helpers :: The app is a normal web page. Helpers can see it and press its buttons. :: a robot finger pressing a web button
- What works today :: Laptop, server and cloud from one list. Rust parts with twins in several apps. :: green tags on a short list
- What is still rising :: Other people's apps run more and more often. It is alpha and changes most days. :: dough rising in a bowl
- One lamp. Every socket. :: Write the app once. Let the plug worry about the wall. :: the lamp from slide one, lit
