# The Example Range
> About fifty apps, from "hello" to 3D games: what each family proves, and why we keep building more.

## A test kitchen, not a menu
- The Example Range :: About fifty apps, from "hello" to 3D games. What they prove, and why we keep building them. :: a long wall of plated dishes
- A test kitchen :: It cooks every dish on every stove, to prove the stoves work. :: a row of different stoves, one pan on each
- Dishes and stoves :: Each app is a dish. The laptop, the server and the cloud are the stoves. :: dish labels and stove labels joined by lines
- A burnt dish names a broken stove :: When a stove breaks, a dish burns, and we see it the same day. :: smoke from one pan, a finger pointing at its stove
- Hello world is the smoke alarm :: Nobody orders it. It stays on the menu anyway. :: a smoke alarm on the ceiling

## Five families
- Five kinds of example :: Games, the front door, real tools, the workshop, and other people's apps. :: five family photos on a wall
- Games :: 3D, shared and fast. The hardest test of all. :: a game controller under a magnifier
- The front door :: One account and one list of apps, for every app. :: a front door with a library card slot
- Real tools and the workshop :: Apps for work, and heavy apps for music, 3D and circuits. :: a toolbox beside a workbench
- Other people's apps :: Apps from popular frameworks, run with no changes. :: a stranger's suitcase, unopened, plugged in

## Games push every part at once
- Fun is a strict boss :: Every game here is "for fun". Every one has found a real bug in the engine. :: a boss with a whistle and a clipboard
- Hide and seek in a real park :: Each player gets only what they can see. :: a park map with fog everywhere but one circle
- A creature brawler :: Folklore beasts with real weight. A robot plays itself thousands of times to keep it fair. :: two beasts squaring up, a robot keeping score
- Skating and disc golf :: Physics the tests can run with no screen, and live wind from the weather service. :: a board on a ramp, a disc curving in the wind
- A rhythm runner and a toy-soldier battle :: Made for a phone first; a code project turned into a battlefield. :: a phone with music notes, toy soldiers on a folder tree

## One game, four ways to play
- Same rules, four places :: One of our games runs the same rules in four ways. :: four panels showing the same game board
- Alone :: The whole game runs inside the one file. :: one person, one laptop
- One couch :: Friends share one screen. :: two controllers, one sofa
- Home network :: One laptop holds the game. Friends on the same network join. :: one laptop with three phones around it
- Online :: The same rules run in the cloud, one room each. Zero arguments about whose copy is right. :: a cloud with small rooms inside

## The workshop: two engines, one answer
- Heavy work :: Sound, rigging 3D models, circuit boards. :: a waveform, a 3D skeleton and a circuit board
- Two engines side by side :: Many workshop apps run a Rust engine and a TypeScript engine together. :: two engines on one bench
- The music app :: It makes sound in both. The two outputs match exactly, sample by sample. :: two waveforms laid exactly on top of each other
- The circuit app :: Much faster with Rust. Still works without it. :: a fast lane and a slow lane, both reaching the finish
- The same soup :: Two cooks, one recipe, and the soup must taste the same to the last grain of salt. :: two bowls, one grain of salt each

## Not only toys
- Boring in the good way :: Games prove it is fast. Tools prove it is dull and dependable. :: a racing car beside a reliable van
- A CRM :: Customers and jobs, with a door for an AI helper built in. :: a card file with a small robot door
- A box fit checker :: Will the order fit the box? It packs boxes inside boxes. :: nested boxes, a tick on the outside
- Shop tools :: 3D product views, and a 3D spin made from phone photos. :: a phone circling a shoe, a 3D shoe spinning
- One engine under all of them :: Work tools and games share the same parts. :: one foundation under several different houses

## The real exam: code we did not write
- Our own apps grade on a curve :: We wrote them for our engine. Strangers' apps do not care. :: a school report with "teacher's pet" crossed out
- Popular frameworks, no changes :: We take apps made with popular frameworks and run them as they are. :: a stranger's app dropped into a socket
- A robot tries real projects :: In a sealed room, it runs projects from the internet and writes down what breaks. :: a robot with a notebook in a glass room
- The goal: first try :: Most real apps should start on the first try. :: a single green tick
- Every break becomes a fix :: A failed project points at a gap in the engine. We fill the gap. :: a crack in a wall, then a neat patch

## Every app is a test that never sleeps

- A broken app points at the change :: The failure names the cause. :: a red app with an arrow to one change
- New idea, new app, new test :: Each new idea becomes an app, and each app becomes a test. :: a three-step circle: idea, app, test
- How the range looks today :: Live: games in the browser, workshop twins. In the oven: strangers' apps. Next: polish. :: green, amber and grey tags
