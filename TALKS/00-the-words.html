Talk 0 · Rusty Buns talks

The Words

Every word the other talks use. One plain sentence each, and an everyday picture.

Read this once. After that, nobody in the room has to nod along and hope.

Six words for everything

The basics

App

A program you use, like a game or a website.

Server

A computer far away that apps talk to.

Like: the kitchen behind a restaurant.

The cloud

Servers you rent by the second. Someone else looks after them.

Like: a taxi instead of a car.

Code

The written instructions that make an app.

Like: a recipe.

AI helper (agent)

An AI that reads and writes code when you give it a job.

Like: a fast, keen apprentice.

Example apps

The games and tools we built to prove the engine works.

Like: the cakes in a bakery window.

The engine

Rusty Buns: a stack stitched together

Rusty Buns is not one tool. It is good tools sewn together. You write the app logic once, then pick what runs it.

TypeScript

The main language. The page and the server both speak it, so each message has one shape, checked at both ends.

Like: both sides of a phone call speaking the same language.

Vite

Builds the page people see. It shows each change the moment you save.

Like: a printing press that also proofreads.

Bun

A fast tool that runs TypeScript and packs an app into one file. A good choice, not a must.

Rust

A strict, fast language. Use it for a server, a client or one busy part. In a web page it runs as WebAssembly.

Like: a race engine you can drop into a family car.

Alchemy

Writes down the cloud pieces as code, then sets them up for you.

Like: a shopping list the shop fills by itself.

Effect

A safety net for jobs that can stop halfway: it retries, times out and cleans up.

Like: a climbing rope.

Rust and Bun are both in the name. Neither one is required. We did say Frankenstein.

The cloud pieces

Where our apps live

Cloudflare

The company whose computers run most of our apps, all over the world.

Worker

A small program on Cloudflare that wakes up when someone visits.

Like: a shop light on a motion sensor.

Durable Object

A tiny always-correct memory in the cloud. One per game room, for example.

Like: the referee's notebook.

The box

One plain server that holds many small games at once, for cheap.

Like: a food hall, not a row of restaurants.

The factory

Where the code gets made

git

The usual way to store code and its history.

Like: "track changes" for code.

codeSplitter

Our git home. Every line has a name tag, so many helpers can edit one file at once.

Agent Office

A 3D office where AI helpers sit at desks. Made by WebDevCody; we run our own version.

Worker (in the office)

One AI helper at one desk, on one job.

Not the same as a Cloudflare Worker. Sorry.

Sandbox

A sealed room for a program. It touches only what you list.

Pull request (PR)

A proposed change, waiting for a check before it joins the main code.

The crew

Helpers with names, but no AI

Mervin

Joins everyone's changes together using rules. Costs no AI money.

Like: a very fast, very fair referee.

Ester

Sorts failing tests by who owns them.

Dexter

Finds where AI money goes and suggests cuts.

Bob

The big second computer. It runs the tests so the main computer stays free.

Bob sometimes naps on battery. Bob is allowed.

They are scripts. We gave them names anyway, because "the merge script" never got a thank-you card.

The players' side

Accounts, friends and rooms

eqosys

One account for all our apps. Your library, saves and friends live here.

Like: a library card that works in every branch.

Qollab

The part that connects players to each other.

Like: the phone lines between houses.

Hub

Your own spot in Qollab. Friends find you there.

Party

A short-lived room with a code. Share it, and friends join your game.

Space

A group that stays, like a club with its own chat.

Library

Your shelf of games in eqosys. Your saves come with you.

Like: a bookshelf that remembers your page.

The game engine

How a shared game stays fair

Physics

The rules for how things move, fall and bump.

Tick

One step of the game. Many per second.

Like: one frame of a flip book.

Server authoritative

The server holds the true game. Your screen shows its best guess between true frames.

Like: the referee's call wins.

Netcode

The code that keeps every player's screen in step over the internet.

Interpolation

Drawing the smooth in-between moments, so motion does not stutter.

Double Dragon

Our inside name for the twin engine: two engines that work as one pair. It gets its own talk.

Lag is what happens when the referee's whistle arrives late. Most of the clever bits are about hiding the whistle.

Shipping

How new code reaches people

Test

A small program that checks another program still works.

CI

Robots that run every test on every change.

Like: a spell-check that never sleeps.

Deploy

Putting new code live, where people use it.

Release rings

New code goes to a few people first, then more, then everyone.

Like: tasting the soup before serving the room.

Manual run

A check that needs the owner's own hands or eyes.

Hill climb

A score we raise round by round, like "how good does this look, out of 10".

That's the dictionary

You now speak Bun.

Every other talk uses only these words. If a talk needs a new one, it comes here first.
