Ship It

Tests, the builder computer, release rings, and the one person who presses deploy.

Many AI helpers write code all day. Exactly one human ships it. The ratio is on purpose.

The thread: lots of change, all day, and the main code never stops. Then the person at the end.
The picture first

Tasting the soup before serving the room

  1. The cook tastes a spoonful. Does this one change work?
  2. The kitchen tastes the pot. Does everything still work together?
  3. One table gets it first. Then more tables. Then the room.
  4. The head chef says yes. Only then does it go on the menu.

Nobody has ever been sent home for tasting the soup too often.

The spoonful

Every change gets checked on its own

  • A change is a pull request: a proposal, waiting for a check.
  • Robots check that the code makes sense, and run the tests of every app it touches.
  • A new feature brings one test that walks it the way a person would.
  • Green, and Mervin merges it into the main code. Red, and it waits for a fix.

We test what people do every day, not what a cat could do on a keyboard. The cat is out of scope.

The second kitchen

Bob runs the tests

The main computer runs the office: many AI helpers at once. It has no room left for heavy tests.

  • So a second, bigger computer runs them. We call it Bob.
  • A helper sends its work to Bob as it is. No need to save it anywhere first.
  • Bob also builds the laptop apps, and runs the slow checks overnight.
  • On battery, Bob runs one thing at a time. Low battery, Bob waits.

Bob does not complain. Bob does not take holidays. Bob does occasionally need to be plugged in.

Release rings

A few people first, then more, then everyone

Each ring is a taste test with a bigger table. The soup earns its way to the dining room.

This is the "cute specific": the main code never freezes. Safety lives in rings behind it that only move forward, each one a pointer that waits for the ring below to stay green.
When a ring goes red

The main code never stops

  • A red ring stops moving. Everyone else keeps working.
  • Ester finds which change broke it, and tells the helper who made it.
  • No fix within the hour? Mervin takes that one change back out.
  • Every good build is kept for a while, so going back is a download, not a rebuild.

No all-hands meeting. No blame. One change out, and back to soup.

Who presses deploy

A person. Always.

  1. Helpers write. They do not ship. An AI helper can propose and test. It cannot put code live.
  2. The price comes first. Before a deploy, the tool lists every paid piece. No list, no deploy.
  3. Secrets stay behind a fingerprint. They unlock only when the owner touches the sensor.
  4. Taste is human. "Does this feel right?" is a manual run, for the owner's own eyes.

The robots can do almost everything. The fingerprint stays attached to a person.

Manual runs

Checks that need a person's hands

  • Some checks need eyes: "Is this fun?", "Does this look right on a phone?".
  • Each one gets its own note on the to-do list, with the steps and the time it takes.
  • The owner works through them in one sitting. Yes closes it. No sends it back.
  • The robots check everything they can first. The person only judges taste.

The robots do the dishes. The person decides if dinner was good.
