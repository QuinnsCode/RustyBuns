# Fake agent swarm: replay a real merge-conflict pain, then Mervin it away

The story: the 10-13 cascade. Many workers branched from a stale `main`, every PR conflicted with the one before it,
and the merge queue fell behind. We replay that from this repo's own history with made-up agents (no model, no spend),
show the swarm stuck in a README, then show Mervin settling the round.

Most of the machinery exists. This plan wires it together; it adds one fixture, one generator and one README section.

## What already exists

| Piece | Where |
|---|---|
| Real conflicted merges replayed through the app, compared with what the person committed | `apps/codesplitter/scripts/merge-replay.ts` (`--recent N`) |
| A merge round as a recorded JSON (board stages, verdicts, lanes) | `scripts/mervin-merge.ts`, `.mervin/rounds/*.json` |
| Replay engine with play, pause, step, speed, files streaming in and settling, cards | `src/mervin-replay.ts`, `src/mervin-watch.html` |
| Jam numbers (23% jammed, 51% with 10+ PRs open) and the curve | `scripts/jam-report.ts`, `docs/jams.md`, `docs/jams-curve.svg` |
| Why it matters, with the findings | `docs/mervin-and-ester.md` |

## Steps (about 1,000 agents: the week of October 7 to 14)

1. **Pull the real week.** One read-only pass (`gh`, `git`, like `jam-report.ts`) over the ~1,000 PRs of the week:
   number, title, opened and merged time, files touched, and whether it jammed on `main` or ran red. Write it to a
   compact `swarm-week.json` (one short row per PR; a few hundred KB). Real PR numbers and titles, fake agents.
2. **One fake agent per PR.** A name and a desk number, nothing running. Desks are dots, not cards, so 1,000 fit on
   one screen: a canvas grid, one dot per agent, colour by state (working, waiting on a conflict, red, merged).
3. **Pain, as it happened ("when I hit it").** Replay the week in time order at 1x to 64x: dots light up as PRs open,
   turn conflict-red as they jam, and the open-PR count and wait clock climb. The jam curve from `jam-report.ts`
   (18% jammed with 0-2 open, 51% with 10+) draws live under the grid, so the viewer watches it get worse with the crowd.
4. **The README with 1,000 hands in it.** Zoom into the shared README feature list: the lines every agent added,
   with `<<<<<<<` markers piling up as the crowd grows. Ship it in the README as an animated SVG (GitHub strips JS)
   of the grid going red, with a PNG fallback, generated by `scripts/swarm-readme.ts`, linking to the live replay.
5. **Fighting out ("getting Mervin'd").** Continue the same timeline into the fix: Mervin plans waves, holds the
   ones that must wait, settles the shared-list conflicts by keeping every line, cards only the true judgment
   calls. The grid goes from red to green dot by dot until the queue is 0 and the README is whole again, all 1,000
   lines in it. The real recorded round (`merge-replay.ts`, 5-10 merges) runs inside it as the zoomed-in proof.
6. **Numbers panel.** Before and after from `jam-report.ts`, plus the honest 13% Mervin settles to other text.
7. **Wire it in.** A chapter on `#/demos`, plus a README `## Features` entry; then `bun run docs`.
8. **Test.** One journey: load the week file, play it to the end, expect every PR merged and no conflict left except
   declared cards. The `Player` (`mervin-replay.ts`) steps one event per PR file today; for 1,000 PRs add a batched
   `tick` so a frame draws many events, and unit-test only that corner case.

## Decisions

- Window: the whole week (decided: "like 1000").
- README format: animated SVG, still open. GIF is the alternative.
- Scope: one PR for steps 1-5 and 7; step 6 can follow.

## Not doing

- No real agents, workers or cloud resources, and no model calls.
- No change to Mervin's engine. If the replay shows a gap, it goes to a codeSplitter issue.
- Nothing is merged or deployed from this branch; the owner reviews the PR.
