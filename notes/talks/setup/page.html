1
Start with someone else's app

Agent Office, swapped onto Rusty Buns

Agent Office is an MIT cartoon 3D office where Claude Code workers sit at desks. It is a Node server with PTYs, WebSockets and a 3D client. I didn't fork it. Rusty Buns boxes it into one file for Mac and Linux, then my game moves in.

Upstream
Node, npm ci, native PTY build on the server
→
Rusty Buns-ified
One Bun binary. Copy it to a box, double-click it.

One line in their code

rustybunsify.ts adds a single push to the office's worker constructor. Everything else reads the worker's own public fields, so the office's logic is untouched.

My game's cast at the desks

Each worker's blob becomes an enemy from my game: a skeleton, a Voidmire, a void wolf or the Bound Druid. I'm Qoa. Walking, idle and the two attacks map to what the worker is doing.

Swaps without losing terminals

An update is a SIGTERM. The terminals live in a detached pty host, so the new office picks them back up with their scrollback.

If the framework can take someone else's Node app, PTYs and all, and make it one file, it can take yours.

2
Then move it into my git

The office becomes a codeSplitter feature

codeSplitter is git for many agents at once: every line is its own record, agents edit the same file live, and each line is blamed by name. The office's control plane moves onto it. The machines move into containers.

Two front doors, one control plane: the local binary for hands-on work, the hosted office for unattended workers, the board and merging.

3
So the agents can go wild

Put the whole office in a box

The office runs shells and agents as me. In a container it can only touch what I list. office:box reads a permission set, prints the docker run for me to read first, then starts it.

repos
Read-only unless I type rw
env
Names only. The value never hits the command line
network
Allowlist through an egress proxy. Anything else asks with an Allow / Deny card
port
Loopback only, never the LAN
memory, cpus
A fifth of the machine, so a runaway agent can't hog it
the rest
Non-root, all capabilities dropped, read-only root filesystem

Whatever isn't listed isn't there: my home folder, my SSH keys, my other repos, my GitHub login.

4
The fun part

Rusty Buns spawns, tests and destroys itself

Inside the box, agents use the same tool I do. They hire more workers, stand up a stage, test it, and tear it down. Pages hand them their buttons over WebMCP, and codeSplitter's MCP server runs in code mode.

Spawn and destroy

plan, deploy and destroy print a KEPT / REMOVED list first, and anything marked protect: true survives a destroy.

WebMCP

Pages register their actions as tools: the office's triage, the skate park's eight tools, the docs site's reading settings. An agent drives the page without screenshots.

Code mode

Four tools instead of 138. The agent writes one program that calls the rest and returns only what it needs, in a Worker with no network of its own.

1,054tokens to list codeSplitter's tools in code mode, against 30,240
29×less context before the agent does anything
1,200tokens to clear 20 TODOs in a 300-line file, against 36,800 tool by tool

Performant, your way

Rust, TypeScript, both, or either

TypeScript has the widest interop on the web: every framework, every npm package, every binding, with no bridge in between. Rust is for the one path that's too slow. When I use Rust, it always has a TypeScript twin that gives the same answer.
