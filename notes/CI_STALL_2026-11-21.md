# CI stall, reassessed 2026-11-21 (#4136)

The first report (issue #4136) covered 2026-11-02 to 11-09. This one reruns `bun scripts/ci-report.ts` over 2026-11-14 to 11-21,
plus a 1-day window (11-20 to 11-21) for what landed this week. Times are Pacific. The full 7-day report is at the end.

## In short

- **CI is busier, and the wait got worse.** `apps` + `typecheck` did 16,915 job-min of work (was 11,645) and waited 33,468
  job-min for a runner (was 23,064). The median job waited 1.0 min (was 0.4); p90 6.3 (was 3.6). Minutes with a job waiting:
  8% (was 5%), 18% in the last day. The median `apps` run takes 4.9 min of wall time (was 1.8).
- **The biggest user was outside the report.** `desktop-drop.yml` used **at least 11,402 job-min** in the same 7 days: 33 runs,
  1,870 jobs. That's two thirds as much as `apps` and `typecheck` put together. In the last day it was 3,376 job-min against
  3,316 for both of them. Every run was a PR dry run. A PR that touches `scripts/drop.ts`, `scripts/mac/`, the workflow
  or any non-row line of `scripts/ci-apps.ts` dry-built **every** app: up to about 70 jobs a push, 26 of them macOS drop jobs.
  That's why, in the last day, only 8 `apps`/`typecheck` jobs were running at the median while jobs queued:
  the other slots under the 20-job ceiling were busy with drop builds and the hourly ring (1,883 job-min over 7 days).
  **This PR fixes it** (below).
- **Every-app runs: fixed on 11-20, so the 7-day numbers don't show it yet.** 176 of 649 `apps` runs still tested 44+ of 55
  apps (87% of test job-min), set off mostly by `packages/models` (57), `packages/gear` (55), `bun.lock` (37) and
  `packages/util` (31). Since #4533 (11-20 20:48) a `packages/` or lockfile change runs only the packages' tests plus the
  apps the PR touched, and the hourly ring sweeps every app. In the last day the every-app runs left were from CI PRs
  themselves (`ci-apps.ts` 12, `apps.yml` 9).
- **Checkout's share was overstated, in both reports.** GitHub's job API leaves out a step whose name is very long, and
  a test lane's step is named after its whole file list. So every lane past the first read as 0% test, and checkout
  looked bigger than it was. With the gap counted as test time (this PR), checkout is **31%** of job time (37% before
  the fix), and checkout + setup + install is 47%, about 28 s per job. Making the `fetch-depth: 0` jobs shallow is now
  worth about 12 job-min a week: drop it.
- **Main broken, this week.** Two tests failed across many PRs:
  - `apps/playground/test/apps.test.ts` (shelf.json) failed on 8 PRs on 11-16 and 3 on 11-18.
  - `apps/splat-spray/tests/first-room.test.ts` failed 13 times, 9 of them on PRs that didn't touch splat-spray. It
    showed up on five days from 11-16 to 11-20. That's the flake in #4597.

  In the last day no test failed on 3+ PRs.

## What this PR changes

1. **`desktop-drop.yml` dry-runs a sample on pipeline PRs.** `dropSample` in `scripts/ci-apps.ts` picks one app per build
   path:
   - the default Linux cross-compile;
   - a row with its own build command;
   - a Rust cdylib, which builds on one runner per OS.

   That's about 11 jobs instead of about 70. A PR that edits only some apps' rows still dry-runs exactly those apps. For
   every app, run the workflow from the Actions tab with apps `all` (dry by default). The hourly ring smokes only 3 apps'
   binaries, so the trade is real: a pipeline change that breaks one app's build shows at that app's next real drop
   unless someone runs the `all` dry run first. At last week's rate, most of those 11,402 job-min come off the shared ceiling.
2. **`ci-report.ts` counts the time no listed step covers.** A test job's gap goes to test, any other job's to other. So a
   lane's missing test step no longer shows up as checkout.

## 4. What to cut, with numbers

**Checkout depth.** The jobs with `fetch-depth: 0` (plan, scripts, containers-plan, containers) check out in 17 s at the median against 18 s for the shallow ones (the test jobs are already shallow). Making them shallow (plan needs only the merge-base: `fetch-depth: 1` plus `git fetch --depth=200 origin main`, or `filter: blob:none`) saves about **13 job-min** (0%).

**Per-job overhead.** Checkout, setup and install are 46% of all job-minutes: each job pays ~28 s before its first test. 42 app suites finish in under a minute at the median; run them six to a job (one checkout and install for six apps) and they keep five sixths of 3500 overhead job-min: **2917 job-min** saved, and 35 fewer jobs in the queue per full run.

**Every app on a shared change.** 176 of 649 apps runs tested 44+ of 55 apps and spent 12464 job-min on test jobs, 87% of all test job-min. What set them off (176 with a known PR): packages/models 57 (8 importing apps), packages/gear 55 (2 importing apps), bun.lock 37, packages/util 31 (34 importing apps), scripts/ci-apps.ts 19, .github/workflows/apps.yml 14, packages/cli 13 (52 importing apps), package.json 10. Testing only the apps that import a changed package (and still every app for the lockfile, the workflow and ci-apps.ts) saves **4921 job-min**; a nightly all-apps run catches what the import graph misses.

**Suites to run on a schedule.** A suite qualifies when one run of it costs 1.5+ job-min (shards summed), it ran in 10+ runs, and it caught at most 2 failures on PRs that touched it. Nightly costs one run a day; hourly (like `desktop-hourly.yml`) 24.

Across all 56 suites, PR test jobs cost 14353 job-min/wk. Three choices, smallest first:

- **A. Only the picked whole suites go hourly:** two-fronts, skate-tech-park, park-hide-seek, git-recon, alien-disc-golf. Saves 3241 job-min/wk (23%). A PR to one of those apps merges without its tests; a break shows on the next hourly, Ester bisects, Mervin reverts within 60 minutes.
