Release rings · how we ship now

Out of the cave

Agents open hundreds of PRs a week (468 in RustyBuns last week). One PR, then every test, then ship it all no longer fits. Five ideas replace it.

  1. One PR, one dot on mainEach PR proves its own feature and squashes back. A red dot is fixed forward or reverted; main never freezes.
  2. Rings test wider and slowerHourly, nightly and Monday sweeps check what a PR can't, and a commit moves out only after it stays green.
  3. Each PR says how straight through it isA score from what it touches, how well its tests prove it, and how big it is.
  4. Three lanes, side by sideStandby, fast lane and express pass the same checks. Only the wait differs.
  5. Security goes expressA hit on our supply chain ships the same day, every check still run, with your OK.
1 · PRs

One PR, one dot on main

Every worker branches off main and comes back as one squashed commit, after its PR has proved its own feature: typecheck, the touched apps' tests and one journey. So each dot on main is one whole PR, and "which PR broke it" is a short walk. A red dot never freezes main: Ester finds it, its worker fixes forward, or Mervin reverts it after 60 minutes.

3 · The straight-through score

Each PR says how straight through it is

Not every PR deserves the same wait. A menu typo in one game and a rewrite of the deploy CLI are different risks. Each PR gets a score from facts we can already measure (preflight, test-bites --lines, the files it touches, its app's last 30 days), and the score picks its lane. You can always move a PR to a slower lane. Only you put one in express.

4 · Lanes

Three lanes, side by side

Like the lines at a theme park ride: everyone rides the same ride and walks through the same gates. Standby snakes through every soak. The fast lane waits one hour and one night. Express walks straight through, with every sweep run on the spot. No lane skips a check; only the waiting changes. A red in the fast lane drops it into standby.

5 · Security

Security goes express

The slow lanes exist to catch our own mistakes. They are the wrong tool when the danger comes from outside and every hour of soak is an hour exposed.

What sends a PR to express. A published advisory on something we ship, like a web server, a parser or an auth library. A package, GitHub Action or coding tool in our build chain turning out to be hijacked. A host we deploy to leaking tokens, so we rotate and redeploy. When one of these hits us, waiting is the risk.

What express still does. Every sweep runs: the PR checks, the hourly suite and the nightly builds, all at once instead of on the clock. You still give the OK. A red sweep doesn't drop a security fix into standby. It stays in express, and the next fix forward goes first.

What happens after. The commit then soaks in the normal rings like any other, so anything the rush missed turns up the next hour. A dependency bump for an advisory also gets deps-doctor on the spot, not on Monday.
