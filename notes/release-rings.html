Release rings · how we ship

Out of the cave

A PR proves its own feature and lands on main. Then slower, wider sweeps check it, one ring at a time. A commit moves out a ring only after it stays green. You tag what reaches town.

The rings

Each ring runs more tests, less often

If a change breaks something, work doesn't stop. Ester finds which PR did it. That PR's worker fixes it, or after an hour Mervin takes the change back out.

Caveevery PR
  • The code has no type errors
  • Tests pass for the apps it changed
  • The new feature works end to end once
  • All pass: it joins main
Tunnelsevery hour
  • Every app's tests run
  • The desktop app builds and opens
  • Green 3 hours in a row: it moves out
Nightly marketevery day
  • The Mac and iPhone apps build
  • Apps open at phone sizes, websites build
  • Green 3 days in a row: it moves out
Townevery Monday
  • You try it and see if it feels right
  • It ships on npm and as a desktop download
  • It ships when you say OK
The lanes

Same checks, different wait

Every lane runs every test. Only the waiting changes. A small, well-tested change to one app waits less. You can always move a PR to a slower lane.

Standbyabout a week
  • Waits 3 hours, then 3 days
  • Most PRs go here, and every change to how we build, deploy or keep passwords
Fast laneabout 2 days
  • Waits 1 hour, then 1 day
  • For small changes to one app, with tests that would have caught the bug
  • One failed test sends it back to standby
Expresssame day
  • All the tests run at once, then you say OK
  • Only for security holes, in our own code or in code we depend on
  • Only you can put a PR here
