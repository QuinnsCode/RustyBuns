# FM DAW

> **What it proves:** one Rust crate runs as wasm in the audio thread and over FFI on the host, bit for bit the same as the TypeScript engine, and one world class saves your groove on a laptop or on Cloudflare. One of the [Rusty Buns](../../README.md#see-it-work) examples; all of them are in [EXAMPLES.md](../../EXAMPLES.md).

**Live:** https://fm-daw.notryanquinn.workers.dev · on [eqosys](https://eqosys.qntbr.com)

A small FM groovebox: twelve tracks (five drums and seven synths, each FM or analog), a drum machine (grooves and kits), a reverb and delay called Space with a send on every track, an EQ called Shape on the master and on any track, automation lanes, a step sequencer and a piano roll, live recording from the computer keyboard or a MIDI keyboard, and quantize. The sound engine is written twice, once in Rust and once in TypeScript, and you can switch between them while the groove plays.

## Run it

Run every command from the folder named in its step.

1. **Install** (repo root, once, and again after pulling new dependencies):
   ```
   bun install
   ```
2. **Go to the app:**
   ```
   cd apps/fm-daw
   ```
3. **Optional, for the Rust sound engine** (once per machine; needs [rustup](https://rustup.rs)):
   ```
   rustup target add wasm32-unknown-unknown
   bun run build:native
   ```
   Skip this and the app uses the TypeScript engine only. It still works.
4. **Build and launch the desktop app:**
   ```
   bun run desktop:dev
   ```
   This is `bunx rustybuns build desktop --dev --check && bunx rustybuns run desktop`. Turn your speakers down first.

Ship a binary for this machine (about 62 MB on macOS arm64, with the Rust engine inside):

```
bun run desktop:build           # dist/fm-daw-<os>-<arch>
```

### Plain browser with hot reload

`bun run build` makes the whole web app in `dist/client`: it builds the Rust engine to wasm (skipped with a note if cargo or the wasm32 target is missing; the TypeScript engine runs instead), writes the `.rustybuns/vite.ts` boundary plugin (`bunx rustybuns boundary`), then runs Vite. Run it once before `bun run dev`; if you see `Could not resolve "./.rustybuns/vite"`, that's why. Without a world (plain `vite dev`) nothing saves, and bounces download instead.

Jump to a song from the address: `?song=wobble-lab` opens Wobble Lab (also `demo`, `night-shift`, `long-trail`) solo, so it never replaces a sesh's groove, and `&track=6` selects that track (numbered as on screen) with its Perform panel. `bun run manual` opens #2636 this way.

To try the Cloudflare version on your machine, seshes and all: `bun run build`, then `bunx wrangler dev`, open `http://localhost:8787/` (it sends you to a new `/sesh/<name>`), and open that address in a second browser. `--var ROOM_SEATS:1` shows the full-room card.

### Jam in a sesh (online)

- **A sesh is a named room:** a visit to `/` gets a new name, like `/sesh/fuzzy-black-panda`. There are no accounts yet, so the name is the key: keep the link and the groove is there when you come back (30 days after the last visit). Old `?room=` links redirect to `/sesh/<room>`.
- **Live line:** everything in the room edits one groove, and what your hands do is sent to everyone else the moment you do it: notes from the keys, the computer keyboard or a MIDI keyboard, pitch bend (at most 25 a second), stutter, play and stop. Notes another player plays sound here but are recorded only into their take, and when someone leaves, whatever they were holding is let go.
- **The maker's floor:** whoever opens a sesh first is its maker (a key kept in their browser, no account). Everyone plays in a freezone until the maker presses <kbd>Esc</kbd> or **Hold**: then only the maker edits and plays into the room, and everyone else hears it and plays along heard only by themselves. **Freezone** lets them back in. **Close out** ends the jam: everyone else gets a card (play on alone with the groove they had, or start a sesh), the groove is kept, and only the maker gets in, to **Reopen** it.
- **Grants, who plays, edits and mixes:** the maker leads the sesh. The people button in the status bar lists who's in, and the leader turns on each person's **Play** (the live line, takes and the studio's gear), **Edit** (the groove), **Mix** (mutes, solos, EQ, space and squash) and **Lead** (grant the others, hold the floor, set the code), or hands the lead on. Someone without a grant has the floor's (Freezone: play, edit and mix; Hold: listen) and raises a hand for one, which the leader answers Yes or No. The World checks every message against the grants, and they're kept beside the groove and in the backup. In Freezone a restriction only holds for people who keep their name: Hold is the one that locks.
- **Private seshes:** the maker clicks **Public** in the status bar and sets a room code (4 to 32 characters). From then on a joiner types the code first (the maker never does); this browser remembers it, and everyone already in gets a new code the moment it changes. **Make public** takes it off. The World keeps only a salted hash (restored from the backup with the groove), and an address that gets it wrong 5 times waits a minute.
- **Pointers:** you see where everyone else's mouse is, each in its own colour. Yours isn't drawn.
- **Yours alone:** **Save my setup** keeps a copy of the groove in this browser; **Back to my setup** puts it back after a kid or a parent has had a go (in a sesh, for everyone; undo brings theirs back). **Go solo** leaves the sesh for your own project, saved in this browser and never sent; **Back to the sesh** rejoins the shared groove. Accounts come later (`src/ui/mine.ts`).
- **Chat:** a chat box sits bottom right, with the sesh's last 300 lines kept beside the groove. Click the name at its top to pick yours; until you do, you show as `guest` plus four letters. The sesh's maker (the browser that opened it first, the one that can hold the floor) is its host and gets a delete on every line. A deleted line stays where it was, marked deleted, so the log doesn't jump. The log scrolls inside its box: drag the top edge to make it taller, widen it, or close it to a button that counts new lines.
- **You:** your browser keeps a random key, and the room and the profile store only ever see its hash. Your profile (your name, and whether the chat is open, wide and how tall) lives in a Profile Durable Object per person (`src/profile.ts`, `GET`/`PUT /me`), so it waits for you in every sesh. The page also keeps a copy in localStorage. There are no accounts yet; a sign-in can later point more than one key at one profile.
- **Limits:** `ROOM_SEATS` players in a room (16), `MAX_ROOMS` rooms open at once (50) and `MAX_SESHES` seshes kept at all (2,000, the storage cap), all set in `rustybuns.config.ts`. Past any of them, a visitor sees a card with a sign-up list, Try again, and Play alone (your solo project). The Lobby Durable Object (`src/lobby.ts`) does the counting. Read the list with `curl -H "Authorization: Bearer $TOKEN" <site>/signups`, where the token is the optional `SIGNUPS_TOKEN` secret in 1Password; without it, nobody can read the list.
- **Wind back:** **Wind back…** in the status bar plays the groove as it was 1 min, 5, 10, 20, 1 h, 4 h or 1 day ago, here only: your edits wait and the others' keep landing on the sesh's groove, which **Back to now** returns to. The maker (the leader) can **Bring everyone back here**: that's one edit, so undo takes it back. The World keeps the groove as each edited minute began, thinned so a snapshot always sits a little past each rung (`src/rewind.ts`, about 25 at most), and the ladder goes into the backup with the groove. A take that was off every track when the room last emptied comes back silent.
- **Backup:** every sesh is copied to the `fm-daw-seshes` R2 bucket when its room empties, and every 5 minutes during a jam. If a room's Durable Object comes back empty, the groove, its maker and the floor are restored from the bucket, so a closed sesh stays closed.
- The desktop app runs the same World in-process, with no Lobby and no bucket: one room, never turned away, saved to sqlite.

## Play

| Key | Does |
|---|---|
| <kbd>Space</kbd> | play / stop |
| <kbd>A</kbd> to <kbd>'</kbd> | a keyboard (Ableton's layout): white keys on the home row, black keys above |
| <kbd>Shift</kbd> + key | accented note |
| <kbd>Z</kbd> / <kbd>X</kbd> | octave down / up |
| <kbd>R</kbd> | record; with **Count-in** on, one bar of clicks first |
| <kbd>1</kbd> to <kbd>0</kbd> | pick a track (the first ten) |
| <kbd>⌘Z</kbd> / <kbd>⇧⌘Z</kbd> | undo / redo |
| <kbd>V</kbd> <kbd>B</kbd> <kbd>N</kbd> <kbd>M</kbd> (hold) | stutter: repeat the 1/4, 1/8, 1/16 or 1/32 the playhead is in, until you let go |
| <kbd>Esc</kbd> | panic: stop everything, silence every voice (in a sesh you made, also hold the floor) |

- **Song** loads a whole project. **Long Trail** is ten minutes (432 bars) of dark, symphonic, dubby liquid drum and bass at 172 in A minor, a ride through the parks at night, in nine sections: Dawn, Trailhead, Canyon, Starfield, Summit, Dub Valley, Switchbacks, Ridgeline, Last Light. The drums never leave for long (an octave down through most of it, back up for the drops); the violin is there nearly throughout, plucked in the quiet parts and the builds and bowed for its two themes; the trumpet throws Spanish turns into the dub delay; long horn chords bloom underneath; and the big moves are hi-cut and low-cut sweeps across whole sections, written as automation, with one-beat cuts before each drop. **Night Shift** is the same material as a 32-bar loop. Every sound is a patch in `src/themes.ts` and `src/drums.ts`, so the songs are under this repo's license and use no samples.
- **Analog voice:** any track's patch can switch from **FM** to **Analog**: two band-limited saws detuned apart (up to ±50 cents), a sine sub an octave down, and noise, all through a resonant low-pass with its own envelope; one free-running LFO per track (a 50-second sweep up to 20 Hz) on cutoff and pitch, with vibrato fading in over the first 0.3 s of each note; glide and drive. Its amp envelope and level are operator 1's. This is the voice for detuned-saw basses, womps, brass and bowed strings (the noise is the bow) that FM can't make. Rust has it too, bit for bit.
- **Filters for the analog voice:** **SVF** (the 12 dB low-pass above), **Ladder** (four zero-delay one-poles with the feedback solved each sample and a tanh on the input, after Zavalishin's TPT ladder: the fat 24 dB old-school bass filter that growls when pushed), **Vowel** (two formant band-passes; cutoff slides them through oo, oh, ah, eh, ee, so an LFO on cutoff makes the bass talk), and **Diode** (the diode ladder from Zavalishin's chapter on it: four coupled stages, each loaded by the next, solved together each sample; thinner and squelchier than the ladder, the **Acid line**'s filter). The diode ladder was checked against the book before it was tuned: it whistles at a feedback of 17, its peak lands on the cutoff, and it falls 24 dB an octave.
- **Supersaw:** the **Supersaw** knob swaps the two saws for seven, after Adam Szabo's analysis of the 90s original: his measured spread for each saw, his fitted detune curve on **Detune** (gentle for the first half, wide at the top) and his mix curve on the knob itself (the centre saw against the six around it). The big trance lead and pad (**Supersaw lead**, **Supersaw pad**). It costs seven cheap PolyBLEP saws a voice and no `sin`.
- **Wavefolder:** **Fold** sends the oscillators through a sine fold before the filter, the West Coast shaper: past full scale the wave turns back on itself, up to four times, so the sound gets brighter and stranger as the knob comes up (**Folded bass**).
- **Pulses and PWM:** **Shape** fades both oscillators from saws to pulses (a saw minus a shifted saw, so the PolyBLEP smoothing carries over), and **PWM** lets the LFO narrow the pulse down to 5%.
- **LFO:** sine, triangle, saw down or square; free in Hz or **locked to the tempo** (1 bar down to 1/32, with triplets). A locked LFO follows the transport, so a 1/4 wobble peaks on the beat wherever you pressed play; **Restart on note** starts the wobble with each note instead. On an FM patch the same LFO moves modulation depth, for FM growls.
- **Squash** (next to Space): an over-the-top multiband compressor on the master. Linkwitz-Riley crossovers at 120 Hz and 2.5 kHz split the mix into three bands that sum back flat; each band's loud parts come down (4:1) and its quiet ones come up (3:1, up to 16 dB), so tails, breaths and reverb crowd forward and everything gets dense. The highs and lows get a small lift on top. It's written from the textbook design, runs after either engine and before Space (so Rust/TS parity is untouched) and ends in its own limiter at −1 dBFS. 0 is off and costs nothing.
- **Shape** (the tab next to Pattern): the master EQ, up to eight bands drawn over the live spectrum. Double-click the curve for a band (a **low cut** near the bottom end, a **high cut** near the top, a **bell** in between), drag a dot to move it (up and down is gain on a bell or shelf, and resonance on a cut: drag a cut up for a higher Q, a harder corner with a bump on it), roll the wheel over it for Q, Alt-click to bypass it, hold a dot still for a moment to hear only its range (it follows a drag; let go for the whole mix again), double-click it or press Delete to take it out; the strip under the curve sets the selected band exactly. Types: low cut and high cut (3, 6, 9, 12, 18, 24 and on up to 96 dB/oct, every one -3 dB at its corner; from 12 up they are Butterworth stacks, so the passband stays flat, and **Reso** above 0.71 puts a bump at the corner; 3 and 9 are half orders, a chain of seven first-order shelves that stays within 0.06 dB of a true 3 dB/oct slope for eight octaves), low and high shelf, bell (a bump up or a dip down, Q is how narrow; matched to the analog shape, so a bell up at 15 kHz keeps its width instead of narrowing near Nyquist), **notch** (a keyhole that takes a range clean out: low Q sweeps out a wide range, high Q one ringing tone) and **band pass** (only that range gets through: sweep it to find a ring, then notch it). **Phase** draws what the bands do to the phase (a steep cut turns it most; a notch flips it at its centre). Drag or roll a dot while recording and the move is kept as automation on the master, like a Perform move on a track: it plays back in the loop and the bounce, the strip under the dots lists each lane (band and Hz, gain or Q) with a clear button, and taking a band out takes its moves with it. **Shape on** (the picker at the left of its bar) switches from the master to any one track: that track gets its own eight bands, filtered inside the engine before the tracks are summed (so its Space send hears the shaped sound too), saved with the track and in the bounce. In the picker, a track that has a Shape shows a dot after its name. A track's Shape does not listen or automate yet.
  - *How it's built:* every band is a trapezoidal state-variable filter (Andrew Simper's linear trap SVF), which stays stable and click-free while you sweep it, unlike a direct-form biquad. Bands run in series, so their phase shifts add but never cancel into ripples, and their order doesn't change the sound. It's minimum phase with no latency; frequencies are prewarped, so a corner lands where it's drawn, and the curve is the filters' exact digital response (bells near Nyquist narrow a little, and the curve shows that too). Settings glide over 20 ms, switching a band crossfades it, and it ends in its own limiter at −1 dBFS. It's written in Rust (`native/crates/fm_daw/src/eq.rs`, in the same wasm as the engine) and again in TypeScript (`src/engine/eq.ts`): the worklet runs the Rust one with the Rust engine and the TypeScript one with the TS engine, and they match bit for bit. It sits after the engine and before Squash, in the audio thread and the bounce, and is saved with the project (and shared in a sesh).
- **Chorus, flanger or phaser** on every track (**Mod**): the 80s polysynth bucket-brigade chorus, built from the circuit's published figures. One delay line swept by a triangle (I slow, II faster, I+II a fast shallow shimmer), darkened, added on the left and subtracted on the right. **Flange** sweeps the same line shorter (0.3 to 4 ms) and feeds it back, the jet (**Jet pad**). **Phase** sweeps four allpasses from 150 Hz to 3 kHz with feedback, two moving notches (**Phased keys**).
- **Sounds:** **Load a sound** on any track: wobble bass, talking growl, Reese, FM growl, ladder bass, acid line, folded bass, sub, screech, supersaw lead, ladder lead, chorus pad, supersaw pad, PWM strings, poly brass, chorus keys, jet pad, phased keys, minimal stab, blip, dub chord (`src/sounds.ts`). The track keeps its pan.
- **Perform** (under the grid, on the selected track): hold a **stutter**; switch the **wobble rate** on the beat; drag the **pad** (cutoff across, wobble depth up); **bend** up to an octave either way, springing back on release. A MIDI keyboard's pitch wheel bends ±2. **MIDI learn**: turn it on, touch any slider, move a knob or fader on your controller, and that CC drives it on whichever track is selected (log sliders keep their travel). Out of the box the mod wheel is wobble depth and CC 74 is cutoff; the map is kept in this browser, since it belongs to your controller rather than the song. A stutter repeats its slice while the song runs on underneath, so letting go lands where the song would have been. **Record** (R) and your stutter, bend and pad moves become automation on the selected track, so the take plays back the way you played it; the list under the bend shows the track's lanes, each with a button to clear it (undo brings it back). Outside a take, stutter and bend aren't saved. Both engines hear them alike, since the stutter and the lanes live in the sequencer.
- **Wobble Lab** (Song menu): half-time at 140 in F minor, four bars to play over. The wobble's rate is automated so it talks, and a vowel growl answers in bar 4.
- **Vel tone** (every patch): how much harder hits change the sound, not just its level. Analog: the cutoff moves up to 3 octaves either way. FM: modulation depth and feedback scale from nothing to double.
- **Hi-cut and low-cut** on every track: a low-pass closing from 20 kHz and a high-pass rising from 20 Hz, after the track's voices. At 0 they're off. Set them to carve room for one part, or automate them for long sweeps over a section.
- **Automation:** a track can carry lanes (`auto` in the project) that move any parameter along straight lines between points; two points on one beat make a jump, which is how cuts and articulation changes (the violin going from plucked to bowed) are written. The sequencer applies them, so both engines hear the same thing. Songs write them today; there's no lane editor yet.
- **Long songs:** a project can run up to 512 bars. The step grid and piano roll show 8 bars at a time with ‹ › to page, and Bounce renders a song (anything past 32 bars) once instead of four times.
- **Drum machine** (above the step grid): **Groove** writes a pattern onto the five drum tracks and moves BPM and swing to it (liquid roller, late night, half-time, chopped break, steppers, four on the floor). Loops run 1 to 32 bars. Loops of 2 bars or more get the groove's fill in the last bar. **Kit** swaps the drum patches and keeps the pattern. Each is one undo.
- **Space** is a reverb and a dotted-eighth ping-pong delay fed by each track's **Send** (lightly high-passed at 150 Hz), so the kick and bass can stay dry and mono while stabs and leads drown. The tails go wide and drift slowly across the stereo field. Higher Space also means more delay feedback; a saturator in the loop keeps the repeats from running away, and a slow wobble on the delay time bends them a little. The engine renders the send bus next to the mix (Rust and TS match on it too); Space runs after either engine, in the audio thread and in the bounce, and has its own limiter at −1 dBFS.
- **Hear a song without the app:** `bun scripts/listen.ts 3` renders Long Trail to a WAV and plays it (`afplay` on a Mac); `2` is Night Shift. It streams to disk, so ten minutes takes about a minute and little memory. Add a loop count (`bun scripts/listen.ts 2 4`) or `--quiet` to only write the file.
- **Q Amp, guitar amps as circuits:** pedals and tube amps simulated part by part (diodes, op-amps, 12AX7s, the tone stack), each one a board drawn in tscircuit. `/amp.html` plays one live with your guitar or a built-in riff: a clear amp whose tubes glow with each stage, a Noise knob (the first tube's resistors hiss, and the tubes clip the hiss), a push-pull power stage that sags when you dig in (and on Q Clean T, a bias tremolo throbbing in its power tubes), a cab impulse response with a mic you move on the cone, a pedalboard of every pedal, the loop machines and a bench slot (drop a tscircuit board and it becomes a pedal with a knob per pot, or says why it won't play) in one row you reorder by each tile's grip (drag, or the arrow keys), any number on at once, the amp a tile too: what sits after it runs in its effects loop, Q Bucket makes the rest stereo, and each tile shows its share of the audio thread, stage screens (spectrum, analog trace, scope, and a three-band focus), a board view (the pedal's schematic and PCB, where you swap its clipping diodes and capacitors and hear the difference), and a patch under the pedals: drag cables between the guitar, pedalboard, amp head and cabinet, and pull one to hear (and read) what breaks. `src/circuit/patch.ts` is the gear-on-cables layer Qollab Studio's gear room and Load In share: `compile(patch)` gives the chains from each source to each output and the problems (an empty input, an instrument cable used as a speaker cable, a loop, a tube amp with no speaker). Q Drive, Q Fuzz, Q Dist and Q Squeeze (every pedal on the gear room's wall) are also real 9 V boards you can order: `bun scripts/pcb.ts` writes each one's Gerbers, BOM, pick-and-place and a 125B drill template into `circuits/q-<pedal>/`. `bun scripts/amp.ts --play` renders WAVs. `bun scripts/profile-amp.ts` fits an amp's part values back from a recording of it (our own amps with their values scrambled), and `bun scripts/capture-amp.ts` plays the test signal into a real amp, records what comes back and fits our closest amp to it. Not on a track yet; how it works and what's next are in [CIRCUITS.md](CIRCUITS.md).
- **The gear room, a room inside Qollab Studio:** `/studio.html` puts Q Amp's gear in a room you walk in first person (WASD and mouse, or a gamepad, the Load In controls). The amps stand on a wall rack, the pedals hang on the pedal wall, the cab is on the floor and the guitar on its stand. Click a box to pick it up and click again to set it down (on the floor, a shelf or another box); click a jack, walk the cable to another jack and click there, and it hangs between them; look at a knob and drag. Cable as many pedals in a row as you like, or run two side by side on Q Split (each side's send out to its pedals and back into its return, Blend between them; a side cabled straight back is the dry signal). Only the amp and pedals cabled between the guitar and the cab run their circuits, in Q Amp's audio thread, heard from where the cab stands. Q Amp's loop machines (Q Bucket, Q Tape, Q Spring) are boxes too: cable them between an amp's send and return. FM DAW's desk stands by the door with a patch bay of four track inserts: cable a track's send through a compressor, an amp (its line out is the cab and mic) or a tape echo and back into its return, and the room plays that insert from the desk, the riff standing in for the track until the track's own sound reaches the room (#4555). Drop a tscircuit board's circuit JSON in the room (Q Amp's bench pedal comes along by itself) and it stands on the floor as a clear pedal with a knob per pot; cabled in, it plays the board at those knobs. The room is the sesh's studio patch, kept in this browser for now. `qstudio.state()` and `qstudio.bench(json)` for probes.
- **Build a pedal for real, its build sheet:** look at a pedal on the gear room's wall or hold one and press B (or open it from Q Amp's board view) for its build sheet: the schematic, the fab board, the parts list as a table and the Gerber layers. One button downloads a zip a board house and a builder need: `gerbers/`, `bom.csv`, `pnp.csv`, `drill.svg`, `pcb.svg`, the schematic and a short build sheet in plain words (the parts, then drill and solder order). The diodes and capacitor you swapped in Q Amp are in the parts list as your parts, in sockets. A pedal's kit is whatever `circuits/<kit>/` holds (`q-drive/` today, written by `scripts/pcb.ts`), loaded only when its sheet opens; a pedal with no kit folder shows its drawings and says its fab files are not made yet. Its tolerance tab builds the pedal 24 times with parts off their printed values (5% resistors, 10% caps, 20% pots, diode spread) and shades the band around the sim's frequency response, with the spread in output level, so you know how far a build may sound from the sim before you order. `qstudio.sheet(id)`, `qamp.sheet()` and `sheetBand()` for probes.
- **The desk's channels, sends and returns:** Tab in the gear room opens FM DAW's desk (`src/mixer.ts`): a strip per source (you on the guitar for now; each player, instrument and track as the sesh feeds them in) with gain, Shape (low, mid and high bands), pan, two aux sends, a fader (0 dB three quarters up, +6 dB at the top), mute and solo. Each aux comes back on a return strip with its own fader and mute: aux 1 is FM DAW's Space reverb, aux 2 plays whatever is cabled between the desk's `aux-send-2` and `aux-return-2` jacks (a pedal, Q Tape, Q Spring, an amp's line out), run by Q Amp's rig at line level. A muted or soloed-out channel stops its sends too. The desk runs on its own audio thread after Q Amp's, and is kept in this browser. `qstudio.channel()`, `send()` and `returnFader()` for probes.
- **Qollab Studio, the jam room:** `/jam.html?room=<sesh>` is a studio you walk into as your avatar (the eqosys avatar parts; New look picks another, kept in this browser) and jam in with everyone in the sesh. The room is data (`src/studio/rooms/live.ts`): a live room with the kit, keys and a bass rig, a vocal booth, and the desk and couch behind the control room's glass. You walk with the camera over your shoulder; Space or a click sits you at the spot in front of you and the camera goes first person, and then your computer keys (A to ', Z / X octave) or a MIDI keyboard play that spot's FM DAW track on the sesh's live line, so everyone hears it (the kit plays the drum tracks, one home-row key each). V switches the camera. Everyone's position, facing and seat go on the live line about 10 times a second, and a seat someone is in shows them playing it. `qjam.state()` for probes.
- **The lane of the track you sit at:** seated in the jam room, Tab (or the button at the bottom right) opens that track's lane over the room, as in FM DAW: the patch (FM or analog knobs, sounds, randomize), Shape (the track's own EQ), the mixer strip (level, pan, send, mute, solo) and the notes (a piano roll, or the kit's steps at the drums, with a pick for which drum). It is FM DAW's own editors, and every change is an op over the sesh, as the desk's are. The leader's grants hold: knobs and notes need edit, EQ and mute/solo need mix, and without them the lane is read only. You keep playing with it open; Tab or a click on the room closes it. At 390 px it fills the screen. `qjam.lane(open?, tab?)` for probes (`src/studio/lane.tsx`, `lane-model.ts`).
- **Mute in the jam room:** N mutes the room and B mutes the person you look at, or use the list of who's here on the room's page (Esc). Both are for you alone, and your own notes still sound. The leader can also mute someone for everyone: the mute is kept with the grants, the World passes on none of that person's notes, and they're told (`src/studio/mute.ts`, `mute` in `src/grants.ts`).
- **A friend's guitar, live in the jam room:** I (or Plug in your guitar on the room's page) plugs your computer's audio input in, dry (no echo cancelling or levelling). Sitting at the bass it goes into that track's amp, else into the first track with an Amp insert, else straight in. Standing in the vocal booth, I plugs in your mic instead: your voice goes the same way, live and a loop late, but straight in past every amp, with echo cancelling on (a mic hears your speakers; headphones keep the band out of it), and everyone's status line calls it your mic. Your dry signal goes to everyone in the sesh over WebRTC, peer to peer (Opus at 128 kb/s, no silence suppression), and each of them plays it through that track's amp on their own machine, placed where you stand, so everyone hears the same circuit and a knob turn costs nothing on the wire. The World only passes each call's setup to the one person it is for, and sends a listen-only guest's guitar nowhere. Your mutes and the leader's apply to it as to notes. The status line says how far behind each guitar is (half the round trip, the jitter buffer and the codec): up to 30 ms is tight, up to 60 ms loose, and past that it says to press C and hear the band a loop late, where every guitar lands on its beat whatever the trip. A machine that can't run every guitar's amp (the amps over half its audio thread for a third of a second) asks the heaviest friend for their amp's output instead: they swap it onto that call without a new offer, its amp here stands aside, and `qjam.guitars()` marks that call `wet`. Your own guitar always runs through the amp on your machine. That is the **now** way of hearing it; a loop late and at the desk, the next entry, it comes as stamped slices instead. Two players whose networks both refuse a direct path (some mobile networks and offices) go through Cloudflare's TURN relay: the Worker hands each page a day's pass at `/ice`, billed per GB relayed, and without a TURN key (or on the desktop) a call gets STUN alone. `qjam.guitar()` and `qjam.guitars()` for probes; `bun scripts/guitar-check.ts` runs a real call in headless Chrome (`src/guitar.ts`, `src/studio/guitar-line.ts`).
- **One clock for the band, and hearing it a loop late:** the sesh's leader (its maker) is the master clock, like the click in a band's in-ears. Every other page pings the leader through the World (four times a second at first, then every two seconds), keeps the answers that came back fastest, takes their median offset, and moves toward it slowly (2 ms a second at most, never a jump while the groove plays); with no leader in, the World's clock answers (`src/clock.ts`). Beat 0 is the leader's time 0, so every page counts the same beats, and the audio thread's click and loop follow them from what the speakers are playing right now: Enter starts the groove and its click for everyone, and each player's beat 1 lands at the same moment. Notes on the live line carry the beat they were played on, and a plugged-in guitar also goes out in 100 ms slices stamped with theirs (the input's and output's latency taken off, as takes do), as Opus at 96 kb/s through WebCodecs, a quarter of 16-bit PCM's bytes, with one encoder per guitar and one decoder per listener running across the slices so the seams don't click (`src/studio/opus.ts`; a browser with no WebCodecs sends PCM). C picks how you hear the others: **a loop late** (the default: everyone a loop behind, in time), **now** (as it comes, the WebRTC guitar), or, for the leader, **at the desk** (the whole band 150 ms behind, lined up). The audio thread plays each slice from the sample its beat names, with a jitter buffer and a resample of at most 0.5 % fitted to the stamps so a fast or slow sound card can't drift away (Rust in `native/crates/fm_daw/src/remote.rs`, `src/engine/remote.ts` its TS twin, sample for sample); a slice into a track with an Amp insert plays through that amp. A track your own plugin voices goes out the same way, for whoever hasn't got the plugin (a friend who has it installed, in any folder, plays their own copy from the notes: the groove keeps the plugin's id, not only where its maker keeps the file): the host's blocks are folded to mono, cut into stamped 100 ms slices and sent as Opus, after a `plugin` word on the line that tells every other page to keep that track's own synth quiet and play the slices instead, each player's guitar and plugin tracks on lines of their own (heard even listening **now**, 150 ms behind, as they have no call; `src/studio/plugin-line.ts`). `qjam.clock()`, `qjam.listen(mode)`, `qjam.groove(on)`, and `clock` in `qjam.state()` and studio_state, give each page's source, offset, round trip and listening.
- **Qollab Studio's builder, and rooms by what made them:** `/rooms.html` edits a jam-room definition (`src/studio/room.ts`, the one `/jam.html` walks you into): its size, what the floor, ceiling and each wall are made of, panels on the walls (absorbers, a curtain), the inside walls, booths (four walls, glass toward the room and a door) and the seats. Drag seats and booths on the plan; an edit that would break the room (a seat in a wall, a booth sticking out) is refused with the reason. The sound comes from the shape (`src/studio/sound.ts`): the floor is flooded from the seat until walls stop it, so a booth's seat hears the booth, and that space's air and surfaces give how long it rings in each octave band. Clap plays a clap through the seat's impulse response (the first reflections, then a tail falling at each band's ring time), and Walk in opens it in `/jam.html` (`?studio=<id>`, or `?studio=yours` for the one you built, kept in this browser). Rooms are described by what made them, never by a real studio's name: the live room, a scoring hall for an orchestra, a basement with a dead drum booth, a stone room, a wooden barn, the desk concert (a band crammed in behind an office desk among shelves of books, records and toys), the orchestra room (a tall wooden hall with stairs up to the control room's window, a grand piano and mics on tall stands) and the console room (a wood-panelled room round a big analog console, racks of outboard gear, drum machines, a couch and low warm light). Each one says what it is on the card as you walk in; shots in `docs/studios-2026-11-17/`. A room's set dressing is data too (`props` in `room.ts`: shelves, lamps, plants, racks, a console, monitors, stairs, a grand piano, mic stands), drawn by `src/studio/props.ts`. `qrooms.state()` for probes.
- **Agents in the jam room, and making instruments:** an agent is a player too, with the same `studio_*` tools two ways: WebMCP on `/jam.html` (and the Cmd/Ctrl+K palette), or `bun scripts/studio-mcp.ts --sesh https://<host>/sesh/<name>`, an MCP server on stdio that joins the sesh with its own avatar. `studio_state` says who is where, the seats and their tracks, what you may do and the tempo; `studio_sit`, `studio_stand` and `studio_play` (notes in beats, at the sesh's tempo) play a seat on the live line. The leader's grants hold for an agent as for a person, and the World checks them: without one, `studio_ask_to_play` (play, or `can: "edit"` or `"mix"`) raises its hand for the leader's Yes or No. `studio_wind_back(ago)` previews the groove as it was 1 min to 1 day back, for the agent alone. `studio_make_instrument({ name, voice: "fm" | "analog", patch, spot })` puts that patch on a free track (a sound bank name plus knobs) and stands a keyboard synth grown from a seed (`synth` in `@rustybuns/models`) at a clear spot in the room, a seat at its track that anyone can walk up to and play. Made instruments are kept in the groove (`instruments`, up to six) (`src/studio/agent.ts`, `instrument.ts`).
- **Qollab Studio, the front door:** `/jam.html` with no room is the lobby. Sign in with eqosys, see your character (the one kept on your eqosys account, else this browser's look), and **Make a room**: give it a name, pick a studio, and you walk into a new sesh first, so you are its maker and leader. **Copy invite link** in the room gives friends `/jam.html?room=<sesh>&studio=<id>&name=<name>`; it takes them through eqosys sign-in and back into the room, wearing their own eqosys character. Your rooms lists the last few you made or joined. Signed in, the socket carries your eqosys token and the Worker seats you under your eqosys id.
- **Qollab Studio's remote, one screen for a phone:** `/remote.html?room=<sesh>` (the Remote door on every Qollab Studio page) is the sesh's desk in your hand, with no DAW to learn. Play / stop, the room's master level, and a fader and a mute for each of the twelve tracks, named and coloured as on the desk. The track at the seat you sit at in the jam room (as the same person: signed in, or in the same browser) comes up top with its volume, a tone knob (the track's hi-cut) and a space knob (its Space send); sitting nowhere, tap a track's name. It sends the desk's own ops, so the leader's grants hold: Mix for the faders and knobs, Play for the transport. The room's level (`master` in the groove) sits on top of each listener's own master on the desk and in the jam room, and a bounce leaves it out (`src/remote/`). `qremote.state()` for probes.
- **Takes, audio on a track:** **Input** (in the bar over the grid) opens your audio input (a guitar, a mic, or a desk's out through your interface) with no echo cancelling, gating or levelling, onto the selected track. **Rec** then records one pass of the loop from wherever you are, starting at the beat you heard (the output's and input's latency are taken off); a pass cut short by Stop doesn't replace a whole one. The take plays on its track after the engine, at its beat, wrapping round the loop, and mutes and solos with it; the track shows a waveform mark and **Clear take** takes it off (undo puts it back). In a sesh the take's sound goes to the room as 16-bit chunks at 24 kHz before the edit that places it, so everyone hears the same thing, and whoever joins later gets it after the groove. Takes are in the bounce, mixed in as they play. Online, the World copies each whole take to the backup bucket once, so a sesh whose Durable Object is reset gets its takes back with the groove; a solo project keeps its takes' sound in this browser (IndexedDB). Up to four tracks hold a take, 32 seconds each (`src/take.ts`). This is the gear room's step 6: once the amp is a track insert and the desk exists, their output feeds the same recorder.
- **Drums** show as a step grid: click toggles, shift-click accents. Notes you play in freely land between steps and show striped until you quantize them.
- **Synths** show as a piano roll: drag to draw a note (you hear it as you press), click a note to delete it.
- **Quantize** a track to 1/4 through 1/32 or triplets, at any strength. 50% keeps half the feel. **Quantize input** does it as you record.
- **MIDI keyboards** work as soon as they're plugged in (Web MIDI, no driver). On drum tracks middle C plays the drum's own note. MIDI "all notes off" triggers the panic.
- **Your own plugins (VST, AU, CLAP):** **To my DAW** under the keys sends every note played on the desk, yours and everyone's on the live line, to a MIDI port: track 1 on channel 1, track 12 on channel 12. On macOS turn on the IAC Driver in Audio MIDI Setup (Windows: a loopMIDI port), then in your DAW give an instrument track that port and channel as its input. This way the page loads no plugin; your DAW already hosts them. Panic lets go of all sixteen channels. Only played notes go out for now, not the sequencer's.
- **Web plugins (Web Audio Modules), in the browser too:** **Plays** on a track's sound panel also lists **Test Tone (web)** and **A web plugin from a link…**. Paste the address of a [Web Audio Module](https://www.webaudiomodules.com/) (WAM 2, an `index.js` on https) and it plays the track's notes in the page: its parameters are the track's sliders (MIDI learn works), **Editor** opens its own panel, and its sound goes through the track's fader and mute into the master's Shape and Squash. A plugin is code, so one from another site stays silent and asks first: **Let <site> run plugins here** is each player's own yes, kept on that computer, and a friend's groove can't answer it for you. Say yes only for a site you know: its code can do anything the page can, as you. Not yet: a web plugin as an effect on a track (#5359), and its sound in the bounce or on the sesh's live line (#5360). Try it with real sound in headless Chrome: `bun scripts/web-plugin-check.ts`.
- **Bounce** renders four loops to a WAV in `~/Music/FM DAW` (set `FM_DAW_DIR` to change it), and **Show** opens it in Finder. Online, the sesh also keeps its last bounce in the bucket (`GET /sesh/<name>/bounce`, the tempo in `X-Bpm`; a private sesh's needs `?code=`), so a DJ booth's deck in Sound Guy Simulator can play it by the sesh's name. It is deleted with the sesh.

## Where the new voices come from

We looked for open-source Rust synth code to borrow, and checked each license. The engine is written twice (TS and Rust, bit for bit), so we port algorithms rather than add crates. The ladder, diode ladder, vowel filter, pulses, chorus, flanger, phaser, supersaw, wavefolder and Squash here are written from the published designs: Zavalishin's *The Art of VA Filter Design* for the ladder, the diode ladder and SVFs, the textbook flanger (a swept delay with feedback) and phaser (swept first-order allpasses), the Peterson–Barney vowel formants, published measurements of the bucket-brigade chorus, Adam Szabo's *How to Emulate the Super Saw* (2010) for the supersaw's offsets and curves, the textbook sine folder, and Linkwitz-Riley crossovers with up/down compression for Squash. No code was copied, so there are no notices to carry. Good places to look next:

| Project | License | Worth porting |
|---|---|---|
| [fundsp](https://github.com/SamiPerttu/fundsp) | Apache-2.0 (ours) | comb, wavefolding shapers (our phaser and flanger are written from the textbook, not ported) |
| [valib](https://github.com/SolarLiner/valib) | MIT | transistor and OTA ladder variants, saturators, oversampling |
| [Mutable Instruments eurorack](https://github.com/pichenettes/eurorack) | MIT | PWM and variable-shape oscillators, wavefolder, formant speech, swarm (supersaw-like) |
| [nih-plug](https://github.com/robbert-vdh/nih-plug) | ISC (some example plugins GPL) | plugin plumbing, if FM DAW ever ships as a plugin |
| [Web Audio Modules SDK and API](https://github.com/webaudiomodules) | MIT | in use: the host half that lets a page load WAM 2 plugins (`src/ui/wam.ts`), and Test Tone is built on it. Free; each plugin has its own licence, and the page only loads one, never ships it |
| Surge XT, Vital, Odin 2, HexoDSP/synfx-dsp, OctaSine, Dexed | GPL/AGPL | read the papers they cite instead; don't port the code |

## Plugins: what they cost, and whose licence (#4899)

Checked 2026-11-19, before building more on them. Short answer: hosting plugins costs nothing and needs no agreement, as long as FM DAW only loads what a player already has.

| Format | Licence of the format | Fee or agreement | What we do |
|---|---|---|---|
| [CLAP](https://github.com/free-audio/clap) | MIT | none: no fee, no membership, no sign-up ([cleveraudio.org](https://cleveraudio.org/1-feature-overview/_open_licnese/)) | in use on the desktop. The host is written by hand from the published headers (`native/crates/fm_daw/src/clap.rs`), with no crate |
| [VST 3](https://steinbergmedia.github.io/vst3_dev_portal/pages/VST+3+Licensing/Index.html) | MIT since SDK 3.8 (2025-10-29); before that GPLv3 or a signed agreement with Steinberg | none now | not built (#5268). Use SDK 3.8 or later, or a binding made from it; an older binding may still be GPLv3, which would spread to the app. "VST" is a Steinberg trademark: the MIT licence doesn't cover it, so plain text "VST3" to say what loads is fine under their [usage guidelines](https://steinbergmedia.github.io/vst3_dev_portal/pages/VST+3+Licensing/Usage+guidelines.html), and the logo needs those guidelines followed |
| Audio Units | Apple's, part of macOS | none to host | not built (#5268, after VST 3). macOS only |
| [Web Audio Modules](https://github.com/webaudiomodules) | MIT | none | the browser's host (#5359, #5360 for what's left) |

- **The plugins themselves** are each under their maker's licence, and many are paid. FM DAW never ships, uploads or copies one: it loads the file from the player's own plugin folders, and a groove holds only the plugin's id, name and slider values. Keep it that way; a "share this plugin with the sesh" button would be handing out someone's product.
- **The stand-in** (a friend without the plugin hears the player's track on the live line) sends sound, not the plugin. That is what a player does when they stream or record a song, and instrument and effect licences ordinarily allow that (we read no single plugin's licence; a player's own plugin is theirs to check). Sample libraries sometimes forbid passing on single raw samples; a mix through the sesh isn't that, but don't build a feature that records a plugin note by note into a sampler.
- **Money:** nothing to pay anyone. The stand-in costs what a guitar on the live line does (Opus at 96 kb/s through the World, no new service).
- **Not checked:** AAX (needs a signed agreement with its owner and their signing tool; out of scope), and each store's rules if the desktop app is ever sold through one.

## Speaker safety

FM goes from pleasant to screaming in one slider move, so there are limits on every path to the speaker:

- Audio starts only after you click through a "speakers down first" screen, with the master at −12 dB.
- Every parameter is clamped to a range in the engine itself (`RANGES` in `src/engine/params.ts`, mirrored in Rust), so no slider, preset, MIDI message or bad network op can push a value past what's been tested. Modulation depth and operator feedback are capped below where FM turns to noise.
- The master chain blocks DC, smooths the master gain, resets the engine and outputs silence if a sample is ever NaN, then runs a peak limiter (instant attack) with a hard clamp at **−1 dBFS**. The **Limit** lamp lights when it's working.
- Every track starts at gain 0, so a fresh engine is silent until a project loads.
- `test/engine.test.ts` checks all of this: every param at its maximum with every voice on, NaN and Infinity everywhere, and 200 random patches. All of them stay finite and under the ceiling.

## Testing

`bun run bench [seconds]` races the engines in the terminal on each built-in song: Rust over bun:ffi (after `build:native`) and TypeScript under Bun, the same host lanes as the app's engine race.

`bun test test` runs the safety and parity tests. Look for `max |rust - ts| = 0.00e+0` on both the `cdylib` and `wasm` lines; without `build:native` those two skip with a note.

Then check by ear, **speakers down first**:

1. **Sound.** Space plays the demo; the **Limit** lamp should stay mostly dark. Switch the engine to Rust while it plays: nothing should change except the notes sounding at that moment. Sweep the Kick's pitch drop, depth and feedback, and hit Randomize on a few tracks, listening for anything harsh or clicky. Esc silences everything.
2. **Recording.** Press <kbd>7</kbd> (Keys), turn on Count-in, press <kbd>R</kbd>, play along after four clicks; notes appear in the roll. Record a drum with Quantize input off: hits show striped until you quantize them (try 50%). <kbd>⌘Z</kbd> undoes.
3. **MIDI.** Plug in a keyboard: its name appears by the keys without a reload. Play a synth track and a drum track.
4. **Saving.** Change something, quit, run again: it's still there. Bounce, then Show: the WAV sounds like what you heard.
5. **The binary.** `bun run desktop:build`, run `dist/fm-daw-<os>-<arch>`, repeat the above. Engine race should list all four lanes.

`rm -rf ~/.fm-daw` starts over from the demo groove. Not covered yet: Linux and Windows builds.

## Rust vs TypeScript

The golden tests render 8 seconds of the demo groove with each engine, and 8 seconds of Night Shift (the analog voice) over FFI. Both the cdylib and the wasm build match TypeScript **bit for bit** (max difference 0 over 384,000 frames), so switching engines changes nothing you can hear.

**Engine race** renders 20 s of the current groove on each lane. On an M-series Mac: TypeScript in the window about 15× realtime, Rust as wasm about 18×, Rust over FFI on the host about 18 to 21×, TypeScript under Bun about 16 to 19×. Rust's lead is small here because both engines spend their time in the same `sin` and `pow` calls. The interesting part is that the same audio comes out of four runtimes.

## On Cloudflare

`src/worker.ts` serves the page and routes `/ws?room=<name>` to a `World` Durable Object, the same class the desktop runs. Open the same room in two browsers and edits show up in both; the status bar counts who's jamming. Visitors are anonymous: the Worker vouches a random id. One address can open only so many new rooms a minute (per Worker isolate), a room holds `ROOM_SEATS` sockets (16), and a socket sending more than its budget (120 messages a second, big ones cost more) is closed and reconnects to the snapshot. A room nobody opens for 30 days is deleted; the desktop's own groove never is. The page is a plain SPA: the Rust engine runs as wasm in the browser's AudioWorklet, exactly as in the desktop window; only the host's extras (saving bounces to `~/Music`, Show, the Engine race's host lanes) stay desktop-only, and Bounce downloads the WAV instead.

Deploying is yours to run, from this folder: `bunx rustybuns plan` (creates nothing; it lists `[Build]`, `[Worker]` and `[Worker/WORLD]`), then `bunx rustybuns deploy`. Both need a Cloudflare login (`bunx rustybuns login cloudflare`). The deploy's build step is `bun run build`, so the wasm ships when cargo and `wasm32-unknown-unknown` are installed. Send a friend your `https://<the deployed url>/sesh/<name>`: everyone with that link edits one groove. A bare `/` makes a new sesh.

## Known limits

- **The sound has only been checked by numbers**, not by ear: levels, peaks and parity are tested, and a bounce of the demo peaks at −3.8 dBFS. How the kit sounds needs your ears.
- **Switching engines cuts the notes that are sounding**; the groove carries on from the next note.
- **Event timing is quantized to 16 samples** (a third of a millisecond at 48 kHz) to keep the audio thread simple.
- **Edits go to everyone, last write wins.** There's no conflict merging beyond that, and undo is per person.
- **No MIDI clock yet, and MIDI out sends played notes only.** MIDI learn maps sliders only, not the button rows (filter type, LFO shape, chorus).
- **No input monitoring:** you don't hear the input through the app while recording (use your interface's monitoring).
- **Voice stealing can click** when a track plays more than 8 notes at once.
